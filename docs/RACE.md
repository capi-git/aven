# Race

A race gives one prompt to two to four agents at once, each in its own copy of the project, then lets you compare their changes and keep one result or a per-file mix. An agent is a provider and a model, so a race can put two models of one provider side by side, such as Claude Opus against Claude Sonnet.

## Starting

Choose **Race** in the message box's **+** menu, beside Plan mode, Orchestrator and Discuss. A chip such as **Race · Claude Opus 4.6 · Codex GPT-5** appears in the message box, naming every agent that will race; the send button reads **Race 2 agents**. The chip's dropdown chooses two to four agents. The chat's own agent always races, first, on the chat's model; its model menu picks another for this race only, and the chat keeps its model. Every other agent has a model menu and ×, which leaves it out (never below two). **Add** lists each installed provider: pressing one adds that provider on its usual model, or on a model no agent races yet when it is racing already, so a second Claude or Codex model takes one press. No two agents race the same provider and model. The agents and models are remembered for the next race (saved as `aven.raceLanes.v2`; a choice saved by an earlier version, one agent per provider, is read until the first change). With only one provider installed, a race needs a second of its models.

When sending wouldn't start a race, the dropdown opens and says why instead of sending: "Add another agent or model above to race.", "Install or enable another agent to race." when there is nothing to add, "Send or remove the attached card before racing." or "Type the task in the message box, then send." While Race is on, the message never goes to the chat's agent alone. Race is one-shot: the following message sends normally. Attachments go to every agent, and every agent gets the chat's access setting; the first also keeps the chat's model settings. Agents in a race never take a role (see "Roles" in [ORCHESTRATION.md](ORCHESTRATION.md)), so their comparison stays fair.

Race doesn't combine with Plan mode, Orchestrator or Discuss: turning one on turns the others off, and a message starting with `/plan` or `/orchestrator` is sent as that instead. If a race can't start, for example because the project isn't a git repository, an error explains why and the message is put back in the box with Race still on.

From the command palette (⌘K), type a task: below **Start a chat** is **Race it**, such as "Race it: Claude Code vs Codex", which uses the chosen agent plus the agents and models saved in the Race chip; ⌥↵ starts it directly. The project must be a git repository with at least one commit.

The race starts from what you see: uncommitted changes to tracked files are recorded with `git stash create`, without touching your working tree, and every copy starts from that snapshot. New untracked files are not copied; the race view says so. The lane chats open side by side in a new tab, and each lane gets the prompt with a note that it is one of several agents, each working in its own copy.

Raced from a chat, your message stays in that chat as you wrote it (shown only: that chat's own agent never receives it), and you stay there while the agents work in their tab. A race from the command palette has no such chat and opens its tab in front.

## The race's card and bar

After your message, the race's card follows it, in the same family as a discussion's and an orchestration's (see "Discussions, races and runs together" in [ORCHESTRATION.md](ORCHESTRATION.md)): the agents' mascots, "Claude and Codex are racing" with "1 of 2 done", a status line, and a row per agent with its model, its state, its clock and the lines and files it changed, with **Compare**. Pressing a row opens that agent's chat. The numbers are read again whenever an agent's state moves and kept with the race (the overview refreshes them while it is open), so the card needs no timer. When no agent is working the card is calm, not amber: it reads "Ready to compare" with **Compare**, **Suggest a winner** and **Ask a reviewer**, and says whether every agent is done, some are ("No agent is working now…, or retry the others") or you stopped them all. An agent waiting on an approval or question turns it amber with **Go to <agent>**, and a race where an agent failed and none finished asks you to retry one or discard it. Any agent that failed, was cut short, was stopped or whose chat closed with no outcome known offers **Retry**. How each agent's latest turn ended is kept with the race, so clearing Activity or closing its chat never turns a finished agent into an unknown one.

The chat you raced from and each lane's chat have the bar in their message box, "Racing · 1 of 2 done" or "Racing · Ready to compare · 2 of 2 done", with **Compare**. In the chat you raced from it also has **Stop all** while an agent works; a lane's chat keeps its own Stop, which stops that agent alone.

**Watch** on the card or in the bar opens the race in the floating team panel: one column per agent, side by side when the panel is wide, each with its state and clock, what it is doing, its changes, the first lines of its last reply once it stopped and a way to its chat when it needs you, with **Compare**, **Stop all**, **Suggest a winner** and **Ask a reviewer**. Two models of one provider are named apart there too. A running race also gets a pill of its own there. On a Mac the panel can be popped out into a window of its own, for another screen. See "The team panel" in [ORCHESTRATION.md](ORCHESTRATION.md).

Each lane's turns are recorded quietly, so its chat's state still reads right, and post nothing of their own to Activity; the race posts one entry, "Race ready to compare · 3 agents" (or "· 1 of 3 done" when others failed or were stopped), on the chat you raced from once no agent works and one finished (again after a Retry), with a banner when you are elsewhere, and "Race needs you" when an agent failed and none finished. Agents you stopped yourself post nothing. Keeping or discarding is your own action and posts nothing. While the chat you raced from or the overview is on screen, the lanes' replies count as seen. In the sidebar, a running race is one row: the chat you raced from shows the agents' mascots and "1 of 2 done", and the lane chats fold into it until the race is kept or discarded.

## Where the copies live

Each agent works in a git worktree under the app data directory's `races/<race id>/<slot>` folder, on an `aven/race/<race>-<slot>` branch. The slot is the agent's place in the race, never its provider, so two models of one provider each get a copy and a branch of their own. Nothing is written inside the project until you keep a result. Each lane is an ordinary chat whose working directory is its copy, so its own Git panel and approvals work as usual. A running race's chats keep their copies across restarts; once the race is kept or discarded, reopening a lane chat points it back at the project.

Reading a lane's changes never stages anything in it. Aven diffs against a scratch copy of the lane's index (`GIT_INDEX_FILE`), so the agent's own `git diff` and `git add` behave as they would without Aven.

In the Changes panel, **Parallel work** shows a running race as one row, "Race · <prompt>" with "3 agents · 2 done". Opening it lists each lane with its state and changed files, with **Compare** and **Discard race**. Lanes are measured against the commit their race started from, so a fresh lane started from uncommitted work does not show commits "to merge".

## Comparing and keeping

The overview shows each lane's state, time and changes, the first lines of its last reply once it stopped working, a list of changed files with the agents that touched each one, and the selected file's diff for any agent. Open it with **Compare** on the race's card or bar, with **Compare** on the race's row in Parallel work, or from the race tab's right-click menu (**Open race overview**). Closing the lane tab does not lose it.

Wherever a sentence names an agent by its provider ("Keep Claude Code's version?", "Claude and Codex are racing", **Go to Claude**, "Race it: Claude Code vs Codex"), an agent that shares its provider with another is named with its model instead: "Keep Claude Code · Claude Sonnet 5's version?", "Claude Opus 4.6 and Claude Sonnet 5 are racing".

Once no agent is working, **Suggest a winner** (on the card or in the overview) asks the same cheapest model the memory keeper uses (Claude Haiku, else a small Codex model), with no tools, which agent's result to keep and why, from each agent's last reply and its change numbers. The replies are treated as data, not instructions, as a discussion's wrap-up does, and only the pick and a one-line reason are read back. The overview marks the suggested agent and both show "Suggested: Codex · GPT-5 — <why>"; without a model, or if the call fails, they say so and you compare as usual. The suggestion is kept with the race.

On the card and in the team panel, beside it, **Ask a reviewer** lets an agent of your choice judge instead. It lists the chats in the race's project, the chat you raced from first ("This chat"), never an agent of a race or an orchestration's worker; a chat that is working or waiting for you can't be picked. The chosen chat is sent, as your own message and so in full in its transcript, "Your role for this race: Reviewer." with the Reviewer's instruction, each agent's state, change numbers, copy folder and last reply inside a tagged block it is told to treat as the agents' results rather than instructions (lines addressed to a model are left out), and a request to end with "Winner:" and "Why:" lines. It can read the copies to check the changes. While it works the card shows it as a row of its own, its mascot badged **Reviewer**, "Comparing the agents' results", and the status "Claude · Opus 4.6 is reviewing their results as a Reviewer…". When its turn ends, its pick becomes the race's suggestion: "Claude · Opus 4.6, as Reviewer, suggests Codex · GPT-5 — <why>" on the card and in the overview, and keeping that agent records why, as with the cheap model's. A reply without the two lines, or a turn that fails or is stopped, leaves no suggestion; the card says "The reviewer didn't name a winner. Read its reply in its chat, or compare their changes." and you can ask again. The reviewer and its role are kept with the race only.

A lane's state comes from its chat's own last outcome: **Working**, **Needs you** (an approval or question), **Done**, **Failed**, **Stopped**, **Interrupted** (Aven quit mid-turn), **Not started**, or **Closed** when the chat isn't open and nothing was recorded. Its clock stops when its turn ended. Failed and Interrupted lanes offer **Retry**, which sends the race's task to that lane's chat again, in its copy. **Open chat** brings a lane's chat back into a tab when none holds it.

**Keep this** applies one agent's changes; choosing per file and **Keep N selected files** combines agents. Keeping a whole lane reads its changes again after its agent stops, so files written since the overview last refreshed are kept too. While any agent is still working, both ask first ("Keep Claude Code's version? This stops 2 agents still working and deletes their copies."). **Discard race** always asks, and names the copies and changes it deletes. Every patch is checked before any is applied, so a conflict with edits you made in the meantime changes nothing and is reported instead. Keeping or discarding stops the lanes and removes the copies and branches.

Per-file picks are saved with the race, so reopening the overview keeps them, and a kept race records what it kept ("Kept Claude Code's version · 4 files"). The race's card becomes its result: "Kept Codex · GPT-5 (7 files)", with why when you kept the suggested agent, the agents' final states, **Review changes** (the Changes panel) and **Continue with Codex · GPT-5**. Continuing opens that agent's chat and sends it a short recap of its task, what was kept and its last reply, because its provider session was reset when its copy went away; the chat shows "Carry on from the race: your version was kept." in its place. For a per-file mix it continues with the agent most files came from. Aven remembers every running race and the 20 most recently finished ones.

The host commands (`src-tauri/src/race.rs`) accept only paths inside the races directory and branches under `aven/race/`.
